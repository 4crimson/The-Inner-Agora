# The Inner Agora → Платформа консилиумов: Roadmap v2

## Что изменилось со вчерашнего дня

Вчера мы разобрали главный архитектурный разрыв: ядро хорошее, но зашито в философию, и решили это плагинной моделью «kernel → chambers → roles → skills». Это решение остаётся в силе без изменений — v2 его не отменяет, а достраивает вторым измерением, о котором вчера не говорили прицельно:

| | v1 (вчера) | v2 (сегодня) |
|---|---|---|
| Фокус | Как разделить код на ядро и плагины | + Как сделать общение с ассистентом человеческим |
| Единица работы | Chamber / Role / Skill | + Диалог: визард, уточняющие вопросы, интерфейсы |
| Технический долг | Упомянут общо («зашито в философию») | Конкретный реестр из 11 мест с файлами и строками |

Иными словами: v1 отвечает на вопрос «как добавить вторую палату без форка кода». v2 отвечает на вопрос «как сделать так, чтобы разговор с Агорой ощущался как разговор с толковым человеком, а не как ввод команд в консоль» — и заодно выписывает подчистую все места, которые сейчас держатся на скотче.

## Принципы v2 (дополняют 6 принципов из вчерашнего документа)

Старые 6 принципов (не переусложнять, manifest-first, least privilege по палатам, контроль контекста, разделение «голос» и «скилл», безопасность растёт с ценностью совета) остаются в силе. Добавляются два:

7. **Человеческое поведение — это управляемый слот-филлинг поверх LLM, а не regex-угадайка.** Сейчас `detectMode()` в `agora.mjs` — это `if (/максимальн|макс|deep|глубок/i.test(request))`. Это не понимание, это подбор ключевых слов, и он ломается на любой перефразировке. Правильный путь — не писать больше регэкспов, а явно спросить модель (которая и так уже в контуре, раз это Hermes) вернуть структурированный слот: `{chamber, mode, topic, roster, missingSlots}`. Регэксп остаётся только как последний fallback, если LLM-вызов недоступен.
8. **Никаких тихих домыслов.** Если системе не хватает данных, чтобы создать сессию правильно (неясна палата, неясна глубина, неясен состав), она задаёт **один** уточняющий вопрос — не создаёт сессию наугад и не заваливает пользователя тремя вопросами подряд. Это прямо противоречит текущему поведению `detectMode`, который в случае неоднозначности молча берёт `fallback`.

## Фаза 4 — Ядро человеческого ассистента: понимание, визард, распросы, продолжение (2–3 недели)

Это самая важная новая фаза v2 — прямой ответ на сегодняшний запрос. Разбита на слои, потому что «человечность» — это не одна фича, а несколько разных механизмов, которые легко перепутать.

### 4.0 — Спайк: может ли локальная модель в слот-филлинг (0.5 дня, ДО проектирования остального)

Вся фаза стоит на непроверенном допущении: что локальная модель (сейчас gemma-26b с **выключенным** reasoning — это ваше собственное требование для стабильности) надёжно возвращает валидный JSON по схеме. Это совсем не факт.

- [ ] Прогнать 20 тестовых фраз (реальных, из истории чата) через LM Studio с задачей слот-извлечения; замерить долю валидных извлечений и латентность на сообщение.
- [ ] **Порог решения: <80% валидных** → дизайн фазы меняется до начала кодинга: варианты — extractor на облачной модели (компромисс с privacy-first, только для извлечения слотов, не для содержимого совета), few-shot-промпт с одним ретраем при невалидном JSON, или кнопочное/пронумерованное меню как основной путь вместо свободного текста (тогда Фаза 8 поднимается в приоритете выше 4.1).

### 4.1 — Понимание (заменить regex-угадайку структурированным разбором)

- [ ] Убрать `detectMode()` и `requestedVoiceLimit()` (болячки №2, №3) как единственный источник истины. Вместо них — явный вызов модели с задачей вернуть JSON-слоты: `{chamber, mode, topic, philosophers?, missingSlots[]}`. Regex остаётся только как offline-fallback, если вызов недоступен (см. `IMPLEMENTATION_PLAN.md`, раздел 5).
- [ ] Слот `topic` обязателен всегда; `chamber` обязателен, если подключено больше одной палаты; `mode`/`philosophers` — необязательны, есть разумный дефолт (`balanced`).
- [ ] Ошибка на несуществующем ключе философа (болячка №7) превращается в человеческий ответ («Такого голоса нет в текущем составе, вот ближайшие похожие: …»), а не в молчаливую деградацию.

### 4.2 — Распросы (одно уточнение, не больше)

- [ ] Правило: если после слот-филлинга остаётся ровно один `missingSlot` — система задаёт один короткий вопрос и ждёт ответа, не создавая сессию. Если два и более — система предлагает самый вероятный вариант с явной пометкой «предполагаю Х, если не то — поправь» вместо серии вопросов подряд (никто не любит анкету перед каждым вопросом).
- [ ] Явное исключение: команды `/agora ...` всегда работают напрямую без единого уточнения — визард и распросы **дополняют** естественный язык, а не заменяют точные команды.

### 4.3 — Визард первого запуска и создания сессии

- [ ] `/start`-онбординг (сейчас отсутствует, есть только README): 3–4 сообщения, которые объясняют метафору («это не чат-бот, это созываемый совет»), показывают, что можно спросить прямо сейчас, без предварительного чтения документации.
- [ ] Визард создания сессии для тех, кто не хочет помнить флаги: пошагово — тема → палата (если больше одной) → глубина (min/balanced/max) → подтверждение состава. Каждый шаг можно пропустить, ответив сразу всем текстом одним сообщением («хочу глубокий разбор у совета директоров, go/no-go по найму CTO») — визард распознаёт, что все слоты уже заполнены, и не задаёт лишних шагов.
- [ ] Визард — это конфигурация поверх слот-филлинга из 4.1, не отдельная система: одни и те же слоты, разный интерфейс входа.

### 4.4 — Продолжение разговора (follow-up как первоклассный сценарий)

Для ощущения «как человек» это едва ли не важнее визарда. Сейчас архитектура — «вопрос → совет → синтез → конец». Живой разговор — это «а что если…», «а что бы Хайдеггер ответил на это возражение?», уточнение к уже готовому синтезу — **без** создания новой сессии с нуля и без потери контекста.

- [ ] Follow-up к последней сессии: свободная реплика после синтеза распознаётся extractor'ом как продолжение (новый слот `intent: new_session | follow_up | dialogue_with_role | status`), а не как новый вопрос.
- [ ] Технически follow-up — это новая child-задача к тому же root issue (контекст синтеза вкладывается в описание), либо `dialogue` с конкретной ролью, которому передаётся выжимка синтеза. Ядро root→child переиспользуется, нового механизма в Paperclip не нужно.
- [ ] `state.lastSynthesisRef` (уже существует) становится якорем: пока пользователь не начал явно новую тему, реплики по умолчанию трактуются в контексте последней сессии — с явной возможностью сказать «новый вопрос» и оторваться от контекста.

## Фаза 8 — Интерфейсы и Telegram UX (1–2 недели, можно параллельно с Фазой 4 после MVP слот-филлинга)

Это «кожа» поверх «мозга» из Фазы 4 — здесь про то, как разговор физически выглядит в Telegram, а не про то, как система понимает текст.

- [ ] **Спайк (0.5 дня, делать первым в этой фазе):** проверить, поддерживает ли текущий Hermes-plugin-hook (`pre_gateway_dispatch`) отправку `reply_markup`/inline keyboard в Telegram, или он ограничен обычным текстовым ответом. От результата зависит, какой из двух планов ниже реализуется.
- [ ] **План A (если кнопки доступны):** inline-кнопки для выбора палаты/глубины при неоднозначности вместо текстового вопроса; кнопки быстрых действий после синтеза («Показать разногласия», «Углубить», «Новый вопрос по той же сессии»).
- [ ] **План B (если кнопок нет):** пронумерованные текстовые меню («1. Философия 2. Совет директоров — просто ответь цифрой») с детерминированным маппингом номера на слот — тот же эффект без нативного UI.
- [ ] Прогресс-сообщения во время долгого совета («Платон ответил, ждём Декарта и Хайдеггера») вместо тишины до финального синтеза.
- [ ] Пресеты одной командой/кнопкой: «быстрый совет», «глубокое исследование», «совет директоров: go/no-go».
- [ ] Автовосстановление gateway (болячка №6): `guard --fix` запускается проактивно по таймеру/health-check, а не только вручную по факту, что бот замолчал.

## Что не делать (сознательно вне скоупа)

Как во вчерашнем документе — публичный маркетплейс скиллов, автовыбор палаты без права переопределить, один агент на несколько палат одновременно. Добавляется одно новое ограничение специально для v2:

- **Не делать визард ради визарда.** Если пользователь одной фразой уже дал тему, палату и глубину — визард должен молча создать сессию, а не провести человека через 4 шага, которые тот уже закрыл сам. Визард — это сеть безопасности для неполного запроса, а не обязательный ритуал.

## Порядок выполнения

```
Трек QW (быстрые победы) ──── параллельно Фазе 0, первая неделя
   │
Фаза 0 (аудит + регресс-тесты) + Спайк 4.0 (может ли локальная модель в JSON-слоты)
   │
Фаза 1 (roles.json) ── обязательно до Фаз 2/3/7
   │
   ├── Фаза 2 (палаты-плагины) ──┬── Фаза 3 (скиллы)
   │                             └── Фаза 7 (safety per chamber)
   │
   ├── Фаза 4 (человеческий ассистент: понимание → распросы → визард → follow-up)
   │        │
   │        └── Фаза 8 (интерфейсы Telegram — надстройка над Фазой 4)
   │
   ├── Фаза 5 (гибридный routing моделей)
   ├── Фаза 6 (память профиля / per-chat state)
   └── Фаза 9 (observability/cost) — тянется через все фазы
```

Фаза 4 — самая заметная пользователю, и её зависимость от Фазы 2 мягче, чем кажется: пока палата одна, слот `chamber` не нужен вовсе, а слоты `mode/topic/philosophers` работают против текущего `philosophers.json` без миграции. Поэтому 4.0 (спайк) — прямо на первой неделе рядом с Фазой 0, а 4.1 (понимание) можно начинать сразу после — параллельно Фазе 1. Мультипалатная часть extractor'а (слот `chamber`) подключается позже, когда Фаза 2 даст список палат.

## Definition of «идеал» — как понять, что доведено до конца

- [ ] Новая палата добавляется файлами конфигурации в `chambers/`, без единой правки в `agora.mjs`.
- [ ] Новый пользователь получает `/start`, понимает метафору совета и создаёт первую сессию, не открывая README.
- [ ] Система задаёт максимум один уточняющий вопрос на сессию; никогда не создаёт сессию из явно неполного запроса молча.
- [ ] После синтеза можно продолжить разговор свободной репликой («а что если…») — follow-up попадает в контекст последней сессии, а не создаёт новую с нуля.
- [ ] Ни одного захардкоженного абсолютного пути, ни одного вручную дублируемого en/ru словаря вне chamber-манифеста.
- [ ] Regression-набор из Фазы 0 гоняется перед каждым релизом и ловит расхождения автоматически, а не по жалобе в Telegram.
- [ ] `state` изолирован per-chat; два пользователя одного профиля не видят чужой `lastIssueRef`.
- [ ] Gateway самовосстанавливается без ручного `launchctl kickstart` в подавляющем большинстве случаев.
- [ ] Счётчик стоимости/токенов виден в `status` для любой сессии, включая `all`-режим.
- [ ] Каждая high-stakes палата (если появится) физически показывает дисклеймер в тексте ответа, не только в документации.
